从用户反馈出发，整理手机端找歌、连续听歌、音乐整理和社区互动问题，比较 QQ 音乐与 Spotify，最终形成三项功能方案：**歌手作品完整浏览与整理、核心听歌流程推广干扰控制、评论及陌生互动举报反馈**。

## 研究规模与主要发现

19 道问卷题，回收 159 份，最终保留 110 份；另整理 30 条公开反馈（正向、负向各 15 条），归并七类问题。数据取自原项目报告，公开仓库只保留汇总。

- 搜索使用：109 / 110 人；个人音乐管理：72 人；个性化推荐：64 人。
- 广告、弹窗与活动提示：51 人（46.4%），体验评分 2.50 / 5。
- 页面信息与入口问题：37 人（33.6%）。
- 曲库问题：25 人，其中 23 人报告使用或付费变化；该关联用于问题假设。
- 18—30 岁占 91.8%，学生占 75.5%。关系网络与转发渠道形成的样本具有明显构成偏差。

分析采用 3,000 次置换检验，报告 Cramer’s V / epsilon²，对 34 项检验使用 Benjamini–Hochberg FDR 校正。广告问题与行为变化的关联在校正后未达显著；结论保留关联与因果之间的边界。逐行数据和筛选过程文件留在本地，公开读者可以检查汇总口径，无法据此重跑全部统计。

## 决策过程

1. 用用户任务、发生环节及影响结果，将七类问题拆为 12 个需求组。R01 含 A/B 两项子需求。
2. 从影响范围、任务影响、行为影响和证据强度评分，并为核心任务阻断和安全问题设置 P0 门槛。
3. 对照 QQ 音乐和 Spotify 检查产品已有能力、内容依赖、组织方式和商业约束。
4. 重新检查具体反馈，移出证据不足或研发依赖过强的复杂跨端冲突、云盘与版权方案。最终范围以 **2026-09-12 完整版 PRD** 为准；早期评分保留为决策历史。
5. 为三项最终方案建立“场景 → 流程 → 原型 → 埋点 → 验收”对应关系。
