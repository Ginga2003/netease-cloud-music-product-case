# 网易云音乐手机端产品需求文档

> 完整版｜版本 1.0｜2026-09-12  
> 适用范围：网易云音乐手机端  
> 文档状态：需求方案完成；现网表现以 2026-09-12 前后的公开版本与上线前复测结果为准  
> 原型属性：本文中的页面均为需求方案原型

## 一、文档摘要

本次需求围绕三条完整用户任务展开：

| 需求 | 用户要完成的任务 | 已确认的现有措施 | 需要解决的缺口 | 优先级 |
|---|---|---|---|---|
| 需求一：歌手作品完整浏览与整理 | 找到某位歌手的全部作品，筛选、播放并加入歌单 | 歌手页已有热门歌曲、全部演唱和专辑等入口 | 入口较深、热门歌曲范围有限、不同内容类型混排、批量操作范围不清 | P1 |
| 需求二：核心听歌流程的推广干扰控制 | 打开应用后继续播放、搜索或切换歌曲 | 平台已有会员减免、部分页面关闭和推广关闭能力 | 推广触发时机、重复频次、关闭方式及模块控制缺少统一规则 | P1；现网复测后进入开发 |
| 需求三：评论及陌生互动举报反馈 | 遭遇违规内容或骚扰后提交举报并了解处理结果 | 评论和“一起听”等场景已有举报入口，部分案件能够收到最终反馈 | 提交、受理、审核、补充材料和结果之间缺少连续可查的状态 | P0 |

P0 表示涉及用户安全与信任，应优先保证完整闭环；P1 表示核心体验改进，可按照研发资源安排实施。

## 二、背景与证据

### 2.1 研究材料

需求判断采用三类材料：

1. 具有时间、入口、操作过程和后果的公开用户反馈，用于确定问题场景。
2. 当前产品已有能力及公开版本信息，用于判断产品已经采取的措施。
3. 本地问卷数据，用于辅助理解问题可能影响的使用范围。

公开反馈属于定性材料，只能证明相应问题曾在具体场景中出现。问卷样本集中于年轻学生群体，数据不代表网易云音乐全部用户。

### 2.2 需求一的证据

2026 年 7 月的用户讨论描述了完整的查找过程：歌手页面的“全部演唱”需要下滑查找；热门播放和保存范围只覆盖前 50 首；专辑页混入单曲、节目和改编版本；旧专辑缺少有效的筛选与排序。多名参与者补充确认了热门前 50 首和经典作品难找的问题。

本地问卷中，109 人使用搜索歌曲、歌手、专辑或 MV 功能。该数字用于说明查找音乐属于高频任务，不用于证明所有受访者都遇到了歌手页问题。

来源：[2026 年 7 月用户讨论](https://linux.do/t/topic/2582948?tl=en)

### 2.3 需求二的证据

一条 2025 年 App Store 反馈同时描述了后台返回应用时出现广告、会员推广频繁出现以及付费用户希望隐藏演出票、云村等模块。另一条 2024 年投诉记录了“看广告听歌”倒计时、关闭入口不清晰、误跳转和播放期间语音提醒等具体表现。

本地问卷中，51 人选择广告、弹窗和活动提示过多，广告干扰控制平均评分为 2.50 分。问卷结果作为辅助材料，不能替代当前版本复测。

当前 App Store 页面显示 iOS 版本持续更新。广告样式、会员权益和活动策略变化较快，本需求进入开发前必须完成免费用户、VIP 用户和 SVIP 用户的现网复测。已经消失的旧表现从开发范围删除。

来源：[App Store 用户反馈](https://apps.apple.com/cn/app/%E7%BD%91%E6%98%93%E4%BA%91%E9%9F%B3%E4%B9%90-%E6%95%B0%E4%BA%BF%E9%9F%B3%E4%B9%90%E7%95%85%E5%90%AC/id590338362?platform=ipad&see-all=reviews)、[广告操作投诉](https://tousu.sina.com.cn/complaint/view/17377128251?sld=6f47d25757ad9d8df260f2aba6bc7a94)、[当前 App Store 版本页](https://apps.apple.com/cn/app/%E7%BD%91%E6%98%93%E4%BA%91%E9%9F%B3%E4%B9%90-%E6%95%B0%E4%BA%BF%E9%9F%B3%E4%B9%90%E7%95%85%E5%90%AC/id590338362)

### 2.4 需求三的证据

2025 年 App Store 反馈记录了“一起听”场景中的辱骂、性骚扰及未成年人风险；用户称提交举报一周后仍未获得处理方案。2026 年的创作者投诉记录了歌曲评论区中的集中攻击、举报等待和处理结果不确定。该投诉后续补充显示用户最终收到了举报反馈，说明举报能力存在，主要缺口集中在等待过程与状态透明度。

本地公开反馈同时包含对评论故事和社区氛围的正面评价。治理功能需要保护正常表达，并为明确违规、低质量无关内容和个人不喜欢的内容提供不同处理渠道。

来源：[App Store 用户反馈](https://apps.apple.com/cn/app/%E7%BD%91%E6%98%93%E4%BA%91%E9%9F%B3%E4%B9%90-%E6%95%B0%E4%BA%BF%E9%9F%B3%E4%B9%90%E7%95%85%E5%90%AC/id590338362?platform=ipad&see-all=reviews)、[2026 年评论举报投诉](https://tousu.sina.com.cn/complaint/view/17394848186?sld=e7ed16109236bcf8bb64c186cd78a5bc)

## 三、产品目标与范围

### 3.1 产品目标

| 需求 | 产品目标 | 用户获得的结果 |
|---|---|---|
| 需求一 | 缩短歌手完整作品的查找路径，明确筛选与批量操作范围 | 能找到完整作品、区分作品类型，并确认批量操作结果 |
| 需求二 | 建立统一的推广展示规则，减少对播放、搜索和切歌的阻断 | 能关闭当前推广、继续原任务，并管理常用模块 |
| 需求三 | 让举报从提交到结果形成可查询的状态链 | 能确认举报是否送达、是否需要补充材料以及处理是否完成 |

效果指标在灰度前采集 14 天基线，再由产品、运营和研发共同确定目标值。本文定义指标口径，不补写缺少依据的提升比例。

### 3.2 范围

| 需求 | 本期包含 | 本期排除 |
|---|---|---|
| 需求一 | 歌手页入口、作品分类、排序、完整列表、播放范围、批量加入歌单、结果反馈 | 版权采购、内容补录、歌手关注管理、云盘文件管理 |
| 需求二 | 开屏后推广、后台返回推广、会员推广、活动弹层、关闭规则、频次控制、常用模块管理 | 广告定价、会员价格、商业活动选品、完全关闭全部商业内容 |
| 需求三 | 评论和陌生互动举报、材料提交、状态查询、结果反馈、屏蔽、无关内容反馈 | 完整社区处罚制度、执法处置、创作者直接删除所有公开评论、公开被举报人隐私 |

### 3.3 非目标

- 需求一不改变歌曲授权和可播放状态。
- 需求二保留合理的商业展示空间，安全通知、账号风险提示和服务中断通知不受普通推广频次限制。
- 需求三不保证每次举报都会产生处罚；审核结论取决于内容、证据和社区规则。
- 本期不处理音乐云盘歌曲加入歌单、个人音乐跨端冲突和版权替代版本。现有材料不足以支撑这些复杂方案。

## 四、目标用户与核心场景

### 4.1 用户类型

| 用户类型 | 主要行为 | 对应需求 |
|---|---|---|
| 目标明确的找歌用户 | 从搜索、歌曲页进入歌手主页，查找完整作品 | 需求一 |
| 长期整理歌单的用户 | 按歌手或专辑批量收藏歌曲 | 需求一 |
| 免费用户 | 打开应用、返回应用、切歌时可能接触推广 | 需求二 |
| VIP 或 SVIP 用户 | 关注会员减免是否生效，希望控制非核心模块 | 需求二 |
| 评论区参与者 | 阅读评论、举报违规内容、反馈无关内容 | 需求三 |
| 陌生互动参与者 | 使用“一起听”等功能，可能需要退出、屏蔽和举报 | 需求三 |
| 音乐创作者 | 关注自己作品下的攻击性评论及举报进度 | 需求三 |

### 4.2 核心场景

#### 场景一：查找早期专辑

用户从一首歌进入歌手主页，希望找到该歌手早年发行的正式专辑。用户进入“全部专辑”，选择“正式专辑”和“最早发行”，浏览到目标专辑。

#### 场景二：批量整理歌手作品

用户希望把某位歌手的完整歌曲加入自建歌单。页面先显示当前筛选条件和歌曲总数，用户选择全部结果并提交。系统异步处理，完成后显示成功、重复、不可加入和失败的数量。

#### 场景三：打开应用继续听歌

用户从后台返回应用准备切歌。若当前会话已经关闭过同一推广，系统直接恢复播放器；符合展示条件的新推广以非阻断形式出现，用户可以关闭后继续原任务。

#### 场景四：调整常用模块

用户希望保留搜索、推荐、歌单和个人音乐入口，减少演出、直播或社区入口占用。用户进入模块管理，调整顺序和显示状态，保存后立即返回原页面。

#### 场景五：举报违规评论

用户在歌曲评论区发现辱骂或性骚扰内容，提交举报并获得案件编号。随后可在“举报记录”查看受理、审核、待补充和处理结果。

#### 场景六：陌生互动后继续保护

用户在“一起听”中受到骚扰，先退出并屏蔽对方，再提交举报。网络异常时，本地退出和屏蔽立即生效，举报材料保存为草稿，联网后由用户确认提交。

## 六、详细功能说明

### 6.1 需求一：歌手作品完整浏览与整理

#### 6.1.1 完整作品入口

- 歌手主页的主要内容区固定提供“全部歌曲”和“全部专辑”。
- 入口展示内容总量；总量仍在计算时显示“查看全部”，加载完成后补充数量。
- 热门歌曲区保留“播放热门”操作，并明确显示热门范围，例如“热门 50 首”。
- 用户从搜索或歌曲详情进入歌手主页时，入口位置和名称保持一致。

#### 6.1.2 内容分类与排序

全部作品页提供两级控制：

1. 内容类型：全部、正式专辑、EP／单曲、现场、翻唱／改编、节目／声音。
2. 排序方式：最新发行、最早发行、热度。

内容类型由内容库元数据决定。无法判断类型的作品进入“其他”，不混入“正式专辑”。合作专辑和合辑使用标签说明歌手在作品中的身份。

#### 6.1.3 完整列表播放

- “播放当前结果”只播放当前筛选条件下的可播放歌曲。
- 操作前展示歌曲总数；不可播放歌曲保留在列表中并显示状态。
- 大列表采用分页加载和后台建队列，用户无需等待全部封面加载完毕。
- 用户在任务执行中返回上一页，播放队列继续建立；失败时保留已经加入的歌曲。

#### 6.1.4 批量加入歌单

- 用户可全选当前筛选结果，也可逐项取消。
- 页面在提交前显示选中数量、目标歌单和预计重复项处理方式。
- 同一歌曲已存在于目标歌单时默认去重，并计入“已存在”结果。
- 任务完成后显示成功、已存在、因权限不可加入、内容失效和系统失败的数量。
- 系统失败项支持单独重试，成功项不得重复写入。

#### 6.1.5 状态与异常

| 状态 | 页面表现 | 用户操作 |
|---|---|---|
| 加载中 | 保留页面框架和筛选控件，列表使用骨架状态 | 返回、等待 |
| 空结果 | 说明当前筛选无内容 | 清除筛选、切换类型 |
| 部分失效 | 列表保留作品，标注不可播放或已下架 | 查看其他作品 |
| 批量处理中 | 显示任务进度，不锁死页面 | 查看进度、离开页面 |
| 部分成功 | 分项显示结果 | 重试失败项、查看歌单 |
| 服务异常 | 保留筛选条件和已选项目 | 重试、退出 |

### 6.2 需求二：核心听歌流程的推广干扰控制

#### 6.2.1 推广分类

| 类型 | 例子 | 是否纳入频控 | 展示原则 |
|---|---|---|---|
| 商业广告 | 开屏广告、品牌广告 | 是 | 按会话和自然日控制 |
| 会员推广 | 开通会员、升级会员 | 是 | 结合当前权益和用户关闭行为 |
| 活动推广 | 演出、联名、抽奖活动 | 是 | 不遮挡正在使用的播放控制 |
| 激励广告 | 看广告换取限时权益 | 是 | 由用户主动选择后进入 |
| 服务通知 | 服务维护、功能变更 | 单独管理 | 以消息或横幅呈现 |
| 安全通知 | 登录风险、账号异常、未成年人保护 | 否 | 保证送达，可延后处理但不可被普通频控屏蔽 |

#### 6.2.2 展示判断

展示前依次检查：

1. 当前页面是否处于支付、登录、举报、驾驶或其他不适合打断的流程。
2. 当前歌曲是否已经开始播放，用户是否正在操作播放控件。
3. 当前推广在本次会话和自然日内是否达到频次上限。
4. 用户最近是否关闭过同一推广。
5. 当前会员权益是否允许该推广出现。
6. 推广素材是否具备有效关闭入口和正确跳转地址。

任一阻断条件成立时，普通推广不弹出。适合延后展示的内容进入消息中心、首页卡片或播放器下方的非阻断区域。

#### 6.2.3 会话与频次

- 一次使用会话从应用进入前台开始，连续进入后台超过 30 分钟后结束。
- 同一推广在一次会话内被用户主动关闭后，不再以弹层形式出现。
- 不同推广共用弹层总量限制，防止多个活动连续抢占页面。
- 用户主动点击“看广告获得权益”后，激励广告不计入被动弹层频次，但全过程提供返回路径。
- 具体自然日上限由商业化团队根据灰度数据配置，客户端保留硬性兜底上限。

#### 6.2.4 播放不中断

- 歌曲开始播放后，普通商业内容不播放独立语音提醒。
- 播放器的播放、暂停、上一首、下一首和队列入口不被普通推广遮挡。
- 用户从后台返回且歌曲仍在播放时，优先恢复播放器状态。
- 推广关闭后返回触发前页面，保留歌曲、队列、搜索词和滚动位置。

#### 6.2.5 关闭与防误触

- 弹层和全屏素材使用固定关闭区域，最小可点击尺寸为 44 × 44 pt。
- 倒计时结束后关闭按钮立即可用，位置不发生跳动。
- 关闭热区与广告跳转热区不重叠；关闭事件不得上报为广告点击。
- 第三方落地页返回后恢复原页面，不重新触发同一推广。
- 素材缺少关闭配置或跳转校验失败时，客户端拒绝展示。

#### 6.2.6 常用模块管理

- 页面设置提供“常用模块管理”，展示当前可配置模块。
- 用户可调整模块顺序、隐藏可选模块并一键恢复默认。
- 搜索、播放器入口、消息、安全与账号设置属于基础入口，不允许被完全隐藏。
- 新增商业模块默认进入可配置区域；已经隐藏同类模块的用户不被强制恢复。
- 设置保存后立即生效，并在账号登录状态下同步偏好。

#### 6.2.7 现网复测门槛

需求二开始开发前，由产品和测试使用当前正式版本完成以下矩阵：

| 维度 | 取值 |
|---|---|
| 账号 | 未登录、免费用户、VIP、SVIP |
| 场景 | 冷启动、热启动、后台返回、切歌、搜索、播放 VIP 歌曲、进入活动页 |
| 网络 | Wi-Fi、移动网络、弱网、离线恢复 |
| 记录 | 推广类型、出现时间、关闭方式、是否遮挡播放、是否误跳转、是否重复出现 |

复测未出现的旧问题从开发范围移除；复测发现的新问题按相同规则补入。

### 6.3 需求三：评论及陌生互动举报反馈

#### 6.3.1 场景化入口

- 评论长按菜单提供举报、屏蔽用户和内容反馈。
- 私信与“一起听”页面的安全入口保持可见。
- 用户在陌生互动中点击退出后，安全结果页继续提供屏蔽和举报。
- 举报入口自动带入内容标识、被举报账号、场景、服务端时间和客户端版本。

#### 6.3.2 问题分类

| 用户遇到的情况 | 入口 | 后续处理 |
|---|---|---|
| 辱骂、威胁、性骚扰、欺诈、仇恨表达、未成年人风险 | 举报 | 进入审核系统 |
| 评论与歌曲无关、刷屏、重复内容 | 内容反馈 | 用于质量识别、排序和运营复核 |
| 用户个人不喜欢某条内容 | 不感兴趣 | 影响个人展示偏好 |
| 不希望再与某账号接触 | 屏蔽 | 立即执行个人接触控制 |

明确违规类型进入举报系统。低质量与个人偏好具有独立入口，减少举报渠道被无关内容占用。

#### 6.3.3 材料提交

- 用户选择问题类型后，可补充文字说明和关联片段。
- 评论举报默认携带被举报评论及必要上下文，不要求用户重复截图。
- 陌生互动举报携带会话标识和用户主动选择的相关记录。
- 语音材料只使用已经合规留存且明确告知用户的内容。
- 网络失败时保存草稿；草稿不显示“已受理”。

#### 6.3.4 状态模型

| 状态 | 判定条件 | 页面说明 |
|---|---|---|
| 草稿 | 材料尚未提交或提交失败 | 可继续编辑、删除或重新提交 |
| 提交中 | 请求已经发出，服务端尚未确认 | 可离开页面，后台继续等待结果 |
| 已受理 | 服务端生成唯一案件编号 | 显示编号、提交时间和查看入口 |
| 审核中 | 案件进入规则或人工审核 | 显示最近更新时间 |
| 待补充 | 现有材料不足 | 说明需要补充的材料及截止时间 |
| 已完成：已处理 | 审核完成并采取相应措施 | 显示可公开的结果类别 |
| 已完成：未认定违规 | 现有材料未达到违规标准 | 显示可再次反馈或屏蔽的入口 |
| 已关闭 | 重复案件、用户撤回或超出处理范围 | 说明关闭原因和可用渠道 |

#### 6.3.5 结果反馈

- 结果页显示案件编号、举报对象的脱敏信息、场景、问题类型、时间线和结论。
- 平台反馈是否完成处理及可公开的处理类别。
- 处罚时长、关联案件、审核人员和内部风控信号不向举报人公开。
- 未认定违规时，页面继续提供屏蔽、不感兴趣和补充材料入口。
- 通知送达失败不改变案件状态；用户仍可从举报记录中心查询。

#### 6.3.6 退出与屏蔽

- 一起听中的退出先停止本地语音、消息和共同播放同步，再向服务端补传离场状态。
- 屏蔽先在本机隐藏对方并停止新的直接互动，服务端确认后更新为“已屏蔽”。
- 网络异常时显示“本机已隔离，联网后继续同步”。
- 屏蔽属于用户侧保护措施，不代表平台已经判定违规。
- 用户可在隐私设置中管理屏蔽名单。

#### 6.3.7 重复案件与滥用控制

- 同一用户对同一内容重复举报时，系统提示已有案件并允许补充材料。
- 多名用户举报同一内容时，审核系统聚合线索，分别保留每位举报人的状态记录。
- 举报数量用于风险排序和聚类，不能单独生成永久处罚。
- 恶意举报通过现有社区规则处理，正常举报人的身份对被举报人保持隐藏。

## 十、业务规则与异常处理

### 10.1 共通规则

- 页面必须为失败、空状态和退出提供明确出口。
- 用户的筛选、播放、批量选择、推广关闭和举报草稿均需与当前账号及会话正确关联。
- 同一操作重复提交时使用幂等校验，避免重复加入歌曲、重复记录推广点击或重复创建案件。
- 文字、图标和颜色共同表达关键状态，不能只依赖红绿颜色。
- 所有方案原型中的文案由内容、商业化、安全和法务在上线前复核。

### 10.2 需求一异常规则

| 异常 | 处理 |
|---|---|
| 歌手作品数量过大 | 分页加载；播放队列和批量任务异步建立 |
| 内容类型缺失 | 归入“其他”，允许内容运营修正元数据 |
| 批量任务中途断网 | 保留任务与已完成项，联网后重试未完成项 |
| 目标歌单被删除 | 停止写入，提示重新选择歌单 |
| 歌曲重复 | 默认去重，并在结果中单列 |
| 内容在处理期间下架 | 保留条目，计入不可加入或内容失效 |

### 10.3 需求二异常规则

| 异常 | 处理 |
|---|---|
| 第三方广告 SDK 超时 | 跳过展示，继续原任务 |
| 素材无关闭按钮 | 客户端拒绝展示 |
| 关闭后误触跳转 | 立即返回原页面，记录异常素材与点击区域 |
| 会员状态延迟 | 以服务端最新权益为准，争议推广暂停展示 |
| 离线缓存推广过期 | 删除缓存，不展示 |
| 多个推广同时满足条件 | 按安全通知、服务通知、用户主动激励、普通推广排序；普通推广只展示一个 |
| A/B 实验规则冲突 | 采用干扰更低的兜底规则并记录冲突 |

### 10.4 需求三异常规则

| 异常 | 处理 |
|---|---|
| 退出时网络中断 | 本地立即停止互动，后台补传 |
| 屏蔽服务端未确认 | 保持本机隔离，提示稍后同步 |
| 举报提交失败 | 保存草稿，不显示已受理 |
| 案件重复 | 跳转原案件并允许补充材料 |
| 被举报内容已删除 | 案件保留必要证据和原始内容标识 |
| 通知未送达 | 案件状态保持更新，记录中心可查 |
| 材料超过保存期 | 提前提醒；过期后说明无法继续使用的材料 |
| 用户撤回举报 | 记录撤回时间；高风险案件是否继续审核由安全规则决定 |

## 十一、非功能要求

### 11.1 性能与稳定性

- 歌手作品列表采用分页和懒加载，大列表不得阻塞返回、筛选和播放控制。
- 批量加入歌单使用后台任务，页面退出后任务继续；任务状态可重新进入查看。
- 推广服务或第三方 SDK 故障不得阻断播放器、搜索和个人音乐入口。
- 一起听退出和本地屏蔽优先于服务端响应完成。

### 11.2 可用性

- 关键点击区域满足移动端触控尺寸要求。
- “热门 50 首”“全部结果”等操作范围在按钮附近直接说明。
- “提交中”“已受理”“已完成”使用不同文案，避免状态误解。
- 空状态、错误状态和部分成功状态均提供下一步操作。

### 11.3 隐私与安全

- 举报分析只记录必要的匿名标识、场景、内容标识、状态和结果代码。
- 举报材料与普通行为分析数据分区存储并控制访问权限。
- 推广埋点不采集评论内容、私信内容和举报材料。
- 屏蔽关系、案件详情和处理结果按照账号权限隔离。

### 11.4 可配置性

- 内容类型标签、推广频次、会员减免、举报类型和案件状态文案由服务端配置。
- 客户端保留安全兜底：素材异常不展示、普通推广不遮挡播放、退出与屏蔽优先本地生效。

## 十二、数据埋点与效果指标

### 12.1 需求一

| 事件 | 触发时机 | 关键字段 |
|---|---|---|
| artist_all_entry_click | 点击全部歌曲或全部专辑 | 入口、歌手标识、页面位置 |
| artist_filter_change | 修改内容类型或排序 | 类型、排序、结果数量 |
| artist_play_scope_submit | 播放热门或当前结果 | 操作范围、歌曲数量 |
| artist_batch_add_submit | 提交批量加入歌单 | 选中数量、目标歌单匿名标识 |
| artist_batch_add_result | 批量任务结束 | 成功、重复、失效、失败数量 |

核心指标：

- 完整作品入口到达率＝点击全部作品入口的歌手页会话数／歌手页会话数。
- 目标作品操作完成率＝完成播放或收藏的查找会话数／进入全部作品页的会话数。
- 批量加入成功率＝成功加入数量／实际提交数量。
- 部分失败恢复率＝重试后成功的失败项／进入重试的失败项。

### 12.2 需求二

| 事件 | 触发时机 | 关键字段 |
|---|---|---|
| promotion_request | 推广请求进入客户端 | 类型、场景、会员状态 |
| promotion_decision | 决定展示、延后或放弃 | 原因、频次、实验组 |
| promotion_close | 用户关闭推广 | 展示时长、关闭区域 |
| promotion_click | 用户进入推广 | 素材、落地页、点击区域 |
| promotion_task_resume | 关闭或返回后恢复原任务 | 原页面、播放状态、恢复结果 |
| module_preference_save | 保存模块显示与顺序 | 模块类型、操作、账号状态 |

核心指标：

- 会话内重复推广率＝同一推广在关闭后再次弹出的会话数／关闭该推广的会话数。
- 核心任务恢复率＝关闭推广后继续播放、搜索或切歌的会话数／推广关闭会话数。
- 关闭误跳转率＝关闭区域操作后进入落地页的次数／关闭区域操作次数。
- 播放中断率＝推广触发后播放被暂停或控制不可用的次数／播放中推广请求次数。
- 商业转化指标继续保留，并与任务恢复率、启动退出率共同评估。

### 12.3 需求三

| 事件 | 触发时机 | 关键字段 |
|---|---|---|
| safety_entry_open | 打开评论或互动安全菜单 | 场景、入口 |
| safety_action_select | 选择举报、退出、屏蔽或内容反馈 | 动作、场景 |
| report_submit_result | 举报提交成功、失败或超时 | 问题类型、结果代码 |
| report_status_change | 案件状态变化 | 原状态、新状态、更新时间 |
| report_result_view | 用户查看案件结果 | 结果类别、通知来源 |
| block_sync_result | 本地和服务端屏蔽状态变化 | 场景、网络、结果 |

核心指标：

- 举报受理成功率＝生成案件编号的举报数／用户确认提交的举报数。
- 受理确认时长＝用户提交到服务端生成案件编号的时间。
- 审核完成时长＝案件受理到进入完成状态的时间。
- 结果可见率＝能够在记录中心查询到结果的已完成案件数／已完成案件数。
- 结果查看率＝用户查看过结果的案件数／已送达结果的案件数。
- 再次接触阻断失败率＝屏蔽后仍发生直接接触的账号对数／已确认屏蔽的账号对数。

### 12.4 数据使用要求

- 上线前采集 14 天现状基线。
- 灰度期同时观察产品指标、商业指标和安全指标。
- 需求二的任何实验不得只以广告点击率作为胜负依据。
- 需求三的“举报量下降”不能单独代表治理改善，需要结合受理成功率、处理时长、重复已认定违规和用户结果查看情况。

## 十三、依赖与风险

### 13.1 需求一

| 依赖／风险 | 影响 | 处理方案 |
|---|---|---|
| 内容元数据分类不完整 | 筛选结果错误 | 建立“其他”兜底及运营纠错入口 |
| 完整作品接口返回量大 | 首屏变慢 | 分页、懒加载、后台建队列 |
| 批量写入能力不足 | 任务超时或重复 | 异步任务、幂等标识、失败项重试 |
| 可播放状态变化 | 列表与实际结果不一致 | 播放或加入前重新校验 |

### 13.2 需求二

| 依赖／风险 | 影响 | 处理方案 |
|---|---|---|
| 商业化收入下降 | 推广频次规则难以推进 | 灰度比较转化与任务恢复，保留非阻断展示 |
| 第三方广告 SDK 不受控 | 关闭、跳转和返回异常 | 客户端展示前校验及故障熔断 |
| 会员权益口径不统一 | 付费用户看到不应出现的推广 | 统一权益服务与实时校验 |
| 模块过度隐藏 | 新功能失去发现机会 | 保留推荐入口、恢复默认和新功能说明 |
| 旧反馈已经修复 | 开发无实际价值 | 以当前版本复测作为立项门槛 |

### 13.3 需求三

| 依赖／风险 | 影响 | 处理方案 |
|---|---|---|
| 审核系统缺少标准状态 | 前台无法持续反馈 | 统一案件状态与更新时间 |
| 审核容量不足 | 状态可查但等待过长 | 按风险等级分队列，建立超时升级 |
| 结果披露过多 | 泄露隐私或风控规则 | 只公开必要状态和高层级结果 |
| 举报被滥用 | 正常表达受到影响 | 举报量只作线索，保留证据审核与申诉 |
| 创作者管理权过大 | 正常批评被任意删除 | 创作者使用屏蔽、内容反馈和举报；公开删除由平台规则决定 |

### 13.4 团队依赖

| 团队 | 主要责任 |
|---|---|
| 客户端 | 页面、状态、缓存、任务恢复和本地安全兜底 |
| 内容平台 | 歌手作品关系、内容类型和可播放状态 |
| 歌单服务 | 批量写入、去重、幂等和结果明细 |
| 商业化 | 推广类型、素材、频次和商业指标 |
| 会员系统 | 权益判断与推广减免 |
| 社区安全 | 举报分类、审核规则、状态和处理结果 |
| 客服与运营 | 用户反馈、内容纠错、案件补充和异常处理 |
| 数据 | 事件口径、基线、灰度看板和异常监控 |
| 法务与隐私 | 广告展示、举报材料、结果披露和保存期限 |

## 十四、验收标准

### 14.1 需求一

| 编号 | 验收条件 |
|---|---|
| 1.1 | 歌手主页可在首屏或首屏后一屏找到“全部歌曲”和“全部专辑”；热门区域明确显示范围 |
| 1.2 | 用户可以筛选正式专辑、单曲、现场、翻唱／改编和节目，并按最新、最早或热度排序 |
| 1.3 | 播放操作提交前能够确认作用于热门歌曲或当前筛选结果；不可播放歌曲具有状态说明 |
| 1.4 | 用户可将当前筛选结果批量加入歌单；重复、失效和失败项分开统计 |
| 1.5 | 页面返回、应用切换和网络恢复后，筛选、排序和未完成任务不会无提示丢失 |

### 14.2 需求二

| 编号 | 验收条件 |
|---|---|
| 2.1 | 所有中断型商业内容均能识别推广类型、场景、会员状态和配置来源 |
| 2.2 | 用户关闭同一推广后，本次会话不再以弹层形式重复出现；达到频次上限后不展示 |
| 2.3 | 歌曲开始播放后，普通推广不播放独立语音，不遮挡播放、暂停、切歌和队列入口 |
| 2.4 | 关闭按钮位置稳定且具备有效触控区域；点击关闭不会触发广告落地页 |
| 2.5 | 用户可以隐藏、排序和恢复可配置模块；基础播放、安全和账号入口保持可用 |
| 2.6 | 免费、VIP 和 SVIP 账号按照确认后的权益规则展示推广；权益服务异常时采用低干扰兜底 |
| 2.7 | 当前正式版本复测矩阵完成，复测未出现的旧问题已经从开发项删除 |

### 14.3 需求三

| 编号 | 验收条件 |
|---|---|
| 3.1 | 评论、私信和“一起听”均可在当前场景进入举报，表单自动携带必要上下文 |
| 3.2 | 明确违规、内容无关和个人不喜欢分别进入举报、内容反馈和不感兴趣流程 |
| 3.3 | 只有服务端返回案件编号后才显示“已受理”；失败请求保存为草稿 |
| 3.4 | 用户可查看审核中、待补充和已完成状态，并在待补充状态继续提交材料 |
| 3.5 | 审核结束后显示可公开的结果类别和后续操作；通知失败时记录中心仍可查询 |
| 3.6 | 陌生互动退出和本地屏蔽在网络异常时仍立即生效，联网后继续同步 |
| 3.7 | 重复举报指向原案件并允许补充材料，不重复生成无法区分的案件 |
| 3.8 | 举报数量不会直接触发永久处罚；审核与申诉链路保持独立 |

## 十五、上线与验证计划

### 15.1 阶段一：现状基线

- 使用当前正式版本完成三项需求的现网复测。
- 采集 14 天基础指标，确认页面路径、推广类型、举报状态和技术接口。
- 删除已经解决或无法复现的旧表现。

### 15.2 阶段二：小范围灰度

- 需求一先开放筛选与排序，再开放完整批量任务。
- 需求二先启用客户端频控与防误触，再开放模块管理。
- 需求三先上线案件编号和记录中心，再接入材料补充与完整结果。
- 每项需求均保留原流程回退开关。

### 15.3 阶段三：效果评估

- 需求一同时观察任务完成、接口性能和批量失败。
- 需求二同时观察商业转化、任务恢复、误跳转和启动退出。
- 需求三同时观察受理成功、处理时长、结果可见和再次接触阻断。
- 灰度期间出现安全、数据一致性或大规模任务失败时，停止扩量并恢复原流程。
