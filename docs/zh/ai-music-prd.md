# 网易云音乐手机端产品需求文档

需求一：AI音乐知情权保障｜版本1.1｜2026-11-01

状态：需求评审稿；现网复测、技术评审与用户测试待完成。

## 1. 需求背景与目标

### 1.1 问题背景

听众需要在收听、收藏和购买前了解作品的制作来源。缺少明确标识时，用户需要翻看评论或搜索外部资料，发现信息与预期不符后，还可能重新调整歌单、关注和购买决定。

来源信息同时依赖发布方申报和平台核验。创作者漏报、笼统填写“AI辅助”，以及平台检测的误报和漏检，都会影响标识、推荐偏好和交易披露。本需求围绕来源形成、用户选择和信息纠错建立统一规则。

|S3 调整推荐|来源敏感用户|保存偏好，确认后续推荐变化|

### 2.2 分期范围

|阶段|范围|
|---|---|
|P0 首期|iOS已接入的每日推荐、连续推荐、播放器、创作信息详情；基础来源偏好；参与来源透明交易试点的下载/购买页；来源反馈、更正与售后关联|
|P0 支撑能力|新增上传/音频替换的结构化声明与自动检查；必要复核、申诉、阴性抽检；来源版本、订单快照及缓存更新|
|P1 扩展|搜索结果、歌单及其他客户端的标识覆盖；基于规定核验标准的严格模式推荐池；更多细分偏好和检测方法|
|独立商业评审|依赖制作程度分类的差别定价、基础收听免费试验、补贴与分账调整|

首期沿用既有合法定价和权益。来源透明交易试点对所有申请作品使用同一检查入口，申报人工、辅助或主要生成均纳入；存量曲库按实际影响分批补充信息。

来源判断、艺人身份、内容质量和发行许可分别管理。基本标识、详情、偏好和反馈向免费用户与会员一致提供。

## 3. 功能规则

### 3.1 功能索引

|编号|功能|首期交付|

|AI-01|制作申报|分环节声明、责任主体、版本及修改记录|
|AI-02|自动检查|基础校验、异步初筛、定向复检与失败记录|
|AI-03|来源判定|环节状态、作品级合并规则、疑似退出条件|
|AI-04|标识与详情|推荐、播放器、购买页的一致信息|
|AI-05|推荐偏好|基础排除、保存与撤销、待播推荐更新|
|AI-06|交易披露|明确准入、已有权益检查、披露快照|
|AI-07|来源反馈|就近提交、记录复用、补充与结果查询|
|AI-08|信息更正|来源更新、受影响订单关联及售后进度|
|AI-09|人工与申诉|转人工条件、材料范围、独立复核|
|AI-10|运行监测|阴性抽检、处理成本、积压与规则版本|

### 3.2 制作申报与版本

发布方按歌词、旋律、主唱、伴奏等环节申报“人工制作、含生成式AI、人机结合、无法确认”，无对应环节时标记“不适用”。生成内容在成品中的使用范围需要说明；“AI辅助”需补充具体环节。降噪、修音等处理按实际功能记录，不能仅凭工具名称归类。

完成必填项后可提交。“无法确认”保留为未确认，不授予人工制作标记。日常上传接收可用凭证，不逐首要求完整工程；必要复核和申诉按争议范围索取材料。

同一录音的声明、平台结论及修改历史分别保存。音频替换触发重新检查；只改歌名不会清空原录音证据。平台已有结论须经相应核验流程更正，发布方修改声明不直接覆盖。

### 3.3 自动检查

|层级|对象|处理|结果|
|---|---|---|---|
|L0 基础检查|全部新增上传和音频替换|字段、文件、隐式标识、凭证及版本关系；查询可复用结果|形成来源记录；适用证据可自动支持具体标识，其余进入L1|
|L1 异步初筛|首期接入范围内仍需检测的新增或待查音频|一个经过适用性验证的检测方案，分片段批量执行|记录信号、范围、耗时和失败；可靠疑点进入L2|
|L2 定向复检|初筛疑点、资料冲突、版本变化或新的有效线索|增加检测覆盖、核对同录音关系及对应材料，必要时使用补充方法|确认可支持的事实，或保留疑似/未确认；符合3.10条件才转人工|
|L3 人工复核|未决实质冲突、重要交易等争议、申诉和抽检|核对争议环节及相应材料|确认、更正、补充或保留未确认|

音频检测在后台执行。前台读取预计算来源状态，不在播放或打开详情时启动实时鉴别。超时、不支持、排队与阴性分别记录；失败采用有限重试，未完成检查不记为阴性。

自动采信生成凭证须同时满足：签发方在可信范围内、完整性验证通过、与当前音频版本或已核对素材对应、生成声明及覆盖范围明确。有效签名只解决其中一项；条件不足时不能自动确认。局部素材凭证只支持该部分的来源。

同一音频可复用仍有效的证据。模型更新只使依赖该模型的检测结论按规则回查，不自动推翻独立的可信生成记录。近似匹配提供关联线索，新录音按自身材料判断。

### 3.4 环节状态与作品级判定

每个环节记录发布方声明、平台结论及证据范围。来源结论为D、V、U、H之一；有效生成疑点S单独记录，可与既有结论并存。案件进度另行维护。下表说明对应依据：

|状态|条件|展示与用途|
|---|---|---|
|D 发布方声明|已说明环节来源，基础检查完成，尚未核实且无有效矛盾|生成内容显示“含AI生成内容·发布方声明”；人工声明显示“制作信息·发布方声明”，详情注明未完成核验|
|V 已核实生成|与当前版本对应的材料足以确认生成参与|展示已核实的生成环节|
|S 有效生成疑点|存在经过验证可用的生成信号或材料冲突，争议尚未解决|显示“疑似含AI生成内容”，案件进度单独呈现|
|U 来源未确认|资料或检查不足，且没有足以支持疑似的有效依据|显示“创作来源待确认”|
|H 人工过程核验通过|对应环节的正面过程材料达到规定标准|详情说明核验环节、范围和日期|

H可用于首期申诉或已有材料的核验结果；批量人工认证和严格模式推荐池属于P1。

作品级合并规则：

1. 已核实的生成事实优先显示；其他环节仍有疑点时另提示待核实范围，不用笼统的“更新中”覆盖已知事实。
2. 任何环节的D生成声明、V生成事实或S疑点命中用户排除范围，整首作品退出该推荐。某环节的H不覆盖其他环节。
3. D人工声明和U均不构成无AI保证。基础模式说明其覆盖边界；严格模式要求用户所选范围的全部适用环节达到核验标准。
4. “不适用”环节不参与资格判断；来源不明的实际存在环节不能填成不适用。
5. 检测分数不转换为创作占比。只确认含生成音频时标到这一层，不据此认定全部词曲或所有音轨由AI完成。

### 3.5 疑似复核与状态转换

来源状态与案件状态分别记录。“疑似生成”可以处于核对中、待补充或已有阶段结果，不能统一显示为持续“复核中”。

|复核结果|来源处理|推荐与交易处理|
|---|---|---|
|确认具体生成参与|相应环节转V，撤销已解决的S|按生成范围重算资格|
|正面材料确认人工过程|相应环节转H，撤销被推翻的S|解除由该疑点单独触发的限制；其他有效问题继续处理|
|原信号失效或不足以继续支持疑似|撤销该S；保留有效V/H，无其他核实结论时保留完整无冲突的D，否则U|按新状态重算，不自动授予H|
|原疑点仍有有效依据，参与范围未明|维持对应范围的S，记录依据、有效期和下一次复查|继续适用相应排除或暂缓规则|
|发布方未补材料|不以未补材料单独确认生成，也不据此撤销仍有效的疑点|按现有证据处理；无依据时不得仅靠缺材料维持S|

疑似依据达到复查期时重新评估。复查期或材料补充期届满本身不等于依据失效。继续使用须有有效依据和下一次复查记录；原依据到期失效且无法补充时，按表撤销S。案件超时转交审核负责人并更新进展。首次响应、材料补充及复查期限在上线前确定，见8.2。

### 3.6 标识与来源详情

推荐卡片和播放器在歌名附近显示文本标签，点击进入创作信息详情。详情说明具体参与环节、声明主体、平台核验范围及更新时间，并提供反馈和偏好入口。

同一版本在推荐、播放器、详情和交易页使用同一来源记录。颜色只辅助表达，文本和读屏名称独立说明含义；更新不通过全屏弹窗或语音打断播放。

### 3.7 推荐来源偏好

首期提供“不推荐已标识及疑似AI生成内容”，范围覆盖当前已掌握的词曲和音频生成参与，不将普通音频处理直接归入生成内容。

|所选范围内的来源记录|基础模式P0|严格模式P1|
|---|---|---|
|D，声明生成参与|排除|排除|
|V，确认生成参与|排除|排除|
|S，存在有效生成疑点|排除|排除|
|D，声明人工但未核实；或U|可进入，说明覆盖边界|排除|
|H，规定范围核验通过|可进入|仅当全部适用环节均满足核验条件时进入|

保存以服务端确认为准。成功后更新尚未开始的推荐，在展示或播放前核对当前来源和偏好版本。失败保留选择并提示重试。当前播放、主动点播和收藏保留，用户可撤销设置。

严格模式在合格曲库具备后开放。内容不足时保留偏好，提供主动选歌入口；不以未知来源补足数量。

### 3.8 交易准入与披露

以下规则用于新的来源透明交易试点。必要环节包括词曲来源及成品主唱、伴奏来源；实际不存在的环节标记不适用。发行许可和既有权益独立校验。

|必要环节状态|新增试点交易|披露与恢复条件|
|---|---|---|
|D，完整声明且基础/适用自动检查完成，无有效矛盾|允许|逐项披露发布方声明及尚未核实的范围，不展示平台确认徽标|
|V或H，对应范围已核实|允许|展示已核实范围；其他环节仍按各自状态披露|
|任一必要环节有有效S|暂缓|疑点被解决或其依据失效后，按3.5重算资格|
|任一必要环节为U|暂缓|补充到无冲突的D，或经核验转V/H后重新确认|
|发行许可未通过、必要检查未完成或权益接口失败|暂缓|完成对应校验，重新取得来源和权益快照|

多种状态组合时，任何暂缓条件优先；允许交易要求全部必要环节符合准入条件。D人工与D生成使用相同检查和价格规则，制作声明本身不授予更高价格、补贴或人工认证。后续抽检、申诉和更正继续适用。

未参与试点的存量交易按既有合同及适用要求处理；缺少AI字段不等同于缺少发行许可，页面仍展示可取得的来源状态。

确认购买前，来源、提供方、总价、权益期限和个人使用范围同屏可见。已有会员或同版本购买权益时直接使用。确认期间来源、价格或权限变化，旧确认失效，重新向用户展示；必要快照无法取得时暂缓新付款。个人收听/下载与视频配乐、商业授权分别说明。

### 3.9 来源反馈、更正与售后

来源反馈自动带入歌曲版本、页面入口及当前标识。用户提交具体观察，可附公开链接；相似或仿声线索、订单问题分别转现有版权与客服流程。正式权利通知沿用专门渠道。

同一版本同类问题关联原案件，新材料追加。服务端返回编号后显示已受理；失败保存草稿，结果未知时先查询原请求。案件支持核对中、待补充、已完成及可公开结果。

来源发生重大更正后保留原声明与结论，更新页面和推荐缓存。新试点订单保存当次披露及权益快照；购买时信息缺失或错误的相关订单进入影响核对，向用户提供原订单复核入口。细节补充无冲突时继续原权益。

售后受理、处理结论、退款发起和到账分别记录。退款与其他补救按确认后的规则及实际交易事实处理；来源标签不直接替代版权或退款判断。

### 3.10 人工复核、申诉与抽检

|转入人工的条件|需要完成的判断|
|---|---|
|自动复检仍有实质冲突，无法确定下一步适用范围|核实生成参与范围及相应展示、推荐或交易条件|
|未决争议影响新试点收费、受影响已购用户或重要推广|确认限制范围、依据和恢复条件|
|发布方提出标识或资格申诉|复核原证据与申诉材料，纠正错误结论|
|新材料可核对但自动比对无法解决|核实材料与当前录音是否对应|
|按计划抽中的阴性或低风险内容|发现遗漏并评估检测偏差|
|拟认定故意虚假申报并处罚|综合原声明、矛盾、解释与确认历史作出决定|

凭证足以确认具体生成事实时，可先自动标识并通知发布方，无需逐首人工审核。一个弱信号、产量高或举报量大不单独支持生成认定和处罚。

材料仅限争议环节，允许原始录音、合作方说明等替代完整工程。缺工程不直接认定作弊。申诉由相对独立的审核者处理，结果按3.5回写；不能从一次模型怀疑直接推导故意虚假申报或冻结全部历史收入。

同版本同类案件合并，保留新增线索。抽检包含未被模型标出的内容，记录入样方式和不可判定结果。新生成工具、模型变化或申诉集中纠正时，启动针对性评测与回查。

## 7. 运行容量与依赖

### 7.1 自动处理与审核容量

|措施|成本控制|有效性条件|
|---|---|---|
|复用入库元数据、版本及有效结果|减少重复解析和推理|保留证据、工具和规则的适用范围|
|异步批量单方案初筛|避免前台检测与全量多方法复检|验证曲库适用性，记录失败与覆盖|
|定向复检和材料索取|将较高投入用于未决问题|复核触发条件明确，申诉与抽检可进入|
|同版本同类案件合并|减少重复人工|新增有效材料仍可追加|

容量按队列分别计算：

~~~text
每日人工分钟
  = 未决冲突数 × 平均复核分钟
  + 申诉数 × 平均申诉分钟
  + 抽检数 × 平均核查分钟

每日可用分钟 = 有效审核人数 × 每人有效处理分钟

自动处理成本
  = 去重后初筛量 × 实测单条初筛成本
  + 复检量 × 实测单条复检成本
  + 凭证、存储和运维成本
~~~

容量示算：以下输入均为假设，用于说明计算方法。

|事项|假设输入|工作量|
|---|---|---|
|当日新增待查版本|50,000条|不能由此直接推出人工案件数|
|未决冲突|40案，每案12分钟|480分钟|
|当日申诉|20案，每案15分钟|300分钟，可能来自往日作品|
|抽检|40案，每案8分钟|320分钟|
|总工作量|100案|1,100分钟，约18.3小时|
|可用能力|5人，每人有效处理300分钟|1,500分钟|
|剩余容量|400分钟|约26.7%|

实际案件量、耗时和复杂案件分位数由容量验证取得。申诉和抽检不视为当日新增上传中的固定比例。

### 7.2 过载处理

申诉、受影响交易及重要未决冲突优先处理，随机抽检保留独立预算。先合并重复案件、停止无效重试，再安排低优先级工作并更新进展。

持续超出容量时暂停扩大交易试点或严格模式推荐池，调整处理能力、材料指引和自动复检。积压期间按现有有效证据维持已知、疑似或未确认状态。反馈与申诉入口保持可用，超时按公示规则升级。

### 7.3 技术与业务依赖

|依赖|需确认的事项|影响|
|---|---|---|
|发行与发布后台|声明字段、责任主体、原文件元数据及录音版本关系|决定来源记录能否形成和追溯|
|检测与数据|样本授权、工具适用性、域外误差、吞吐及费用|决定初筛覆盖和复检范围|
|审核与客服|独立复核、材料替代方式、时限和有效案件量|决定申诉、抽检与售后容量|
|来源与推荐服务|统一来源版本、偏好保存、缓存失效和待播检查|决定标识一致与偏好执行|
|交易与权益|许可校验、已有权益、披露快照及影响订单关联|决定新交易准入和更正处理|
|隐私与合规|标识适用、凭证采信、材料处理及补救规则|决定文案与数据处理要求|

普通反馈只带入必要上下文。制作素材、订单和产品分析按角色隔离访问，外部检测的数据处理完成授权评审，材料按批准的留存期限清理。

### 8.3 实施阶段

1. **现状核对。** 记录当前系统、版本、账号、作品ID及页面，核对有明确来源的样本；确认已有标识、偏好、反馈和权益能力，复用等效实现。
2. **规则与容量验证。** 使用有权处理且来源清楚的样本评测，建立阶段与证据记录；新检测方法先完成隔离评测。测量复检、申诉和抽检负荷，确定8.2参数。
3. **任务测试。** 按6.3验证理解、偏好、交易和纠错；同时检查发布方材料负担。
4. **P0灰度。** 先接入可靠来源的展示，再启用偏好与纠错；交易试点对参与作品统一准入，逐步扩大自动检查及旧内容覆盖。
5. **P1评审。** 合格曲库与核验能力具备后验证严格模式、更多入口及细分偏好。价格实验单独评审。

出现成批误标、偏好持续违背、重复收费、快照缺失、材料越权或审核持续超载时，停止扩大对应规则或试点，恢复上一有效规则。保留已确认来源、用户选择和售后查询，相关临时措施逐项复核。
