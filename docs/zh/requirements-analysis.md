# 网易云音乐手机端需求分析

**研究对象：** 网易云音乐手机端  
**文档日期：** 2026-11-01  
**分析范围：** 歌手作品完整浏览、听歌流程推广干扰控制、评论及陌生互动举报反馈  
**对应设计：** [产品需求文档](prd.md)

## 一、研究目标与材料

本报告从找歌、听歌和音乐互动中的具体任务出发，识别任务障碍，核对现有能力，并评估用户价值、业务约束与实施范围。需求池保留前期调研覆盖的七类问题、12个需求组；详细分析集中于作品关联、推广控制和举报反馈三项。

### 1.1 材料与用途

| 材料 | 规模或范围 | 分析用途 | 适用边界 |
|---|---|---|---|
| 体验问卷 | 回收159份，最终保留110份用于分析；19题 | 了解使用目标、问题选择与体验评价，辅助判断关注程度 | 8份因硬性质控问题排除，另41份经进一步筛选未纳入；样本筛选和招募存在偏差 |
| 开放意见 | 110份答卷中65份包含实质改进意见 | 补充用户目标、具体困难和改进方向 | 主题计数表示被提及次数，不能等同于问题发生率 |
| 公开用户反馈 | 30条，其中正向15条、负向15条 | 补充使用场景、后果及需要保留的产品价值 | 平衡取样用于定性分析，正负数量不代表总体满意度 |
| 界面与操作记录 | 网易云音乐iOS 9.6.15；2026-11-01记录 | 核对作品浏览、推广展示、不同账号首屏和举报查询路径 | 单次体验反映相应账号和场景，频率及账号差异需复测 |
| 作品发行资料与平台检索 | BOI官方公告、发行平台艺人页、网易云专辑及艺人列表 | 核对专辑版本、署名与主页关联 | 发行公司、专辑艺人和歌曲参与者须分别确认 |
| 竞品官方资料 | 作品组织、广告控制和举报处理说明 | 比较可借鉴机制及其适用条件 | 官网说明与客户端任务表现分别核验，详见竞品分析报告 |

问卷样本中18—30岁用户占91.8%，学生占75.5%，男性79人。结论适用于本次样本和记录覆盖的场景。公开反馈、问卷自述及操作记录尚未与平台全量曝光、播放或审核日志关联，不能据此估计全体用户的问题发生率或商业损失。

### 1.2 主要调研发现

| 观察项 | 结果 | 对需求判断的作用 |
|---|---|---|
| 明确查找音乐 | 109/110人将搜索列为主要使用功能 | 搜索及其后续浏览属于高频任务，入口可达性需重点保护 |
| 个人音乐管理 | 72/110人将其列为主要使用功能 | 个人音乐入口及既有资产具有持续使用价值 |
| 个性化音乐发现 | 64/110人使用个性化推荐 | 推荐应支持探索与反馈，并保留主动选择路径 |
| 广告、弹窗或活动提示 | 51/110人选择，46.4%；相关体验均分2.50/5 | 支持将推广控制列为重点体验需求；具体机制结合流程记录判断 |
| 页面信息或入口问题 | 37/110人选择，33.6%；页面清晰度与操作便利性均分2.95/5 | 支持核对入口识别与任务路径；不能直接认定某个页面缺少功能 |
| 歌曲可用性 | 25/110人选择；其中23人报告使用行为或付费意愿变化 | 用于确定歌曲可用性的核查任务，版权及其他不可播放原因需结合个案确认 |
| 评论与社区 | 开放意见中出现6次，公开反馈同时包含正向与负向评价 | 需要兼顾音乐交流价值、个人屏蔽与违规处理 |

评分采用5分制，“未使用或不了解”不计入均值。问卷中的广告选择反映用户感知，广告与使用变化的关联在多重检验校正后未达到统计显著，留存收益需通过后续实验验证。

问卷题号与任务来源：第4题用于权益分层，第6题用于识别搜索、歌曲信息、个人音乐及互动任务，第8—9题用于定位体验问题，第15题提供开放意见。题目、统计与具体证据的对应见[用户调研报告](research.md)第8章；竞品机制比较见[竞品分析报告](competitive-analysis.md)。

## 二、用户任务与问题归类

### 2.1 核心任务

| 任务 | 用户目标 | 关键环节 | 需要保障的结果 |
|---|---|---|---|
| 查找特定作品 | 找到歌手、制作主体或合作艺人的相关作品 | 搜索、歌曲署名、艺人主页、专辑列表 | 平台已收录且关系明确的作品能够沿相应艺人路径找到 |
| 快速开始听歌 | 搜索指定歌曲、识别正在播放的音乐，或进入个人音乐 | 启动、首屏识别、入口选择、内容加载 | 关键入口容易辨认，推广不增加强制绕行 |
| 连续收听与查看信息 | 听歌、查看歌名和歌词、切歌、阅读评论后返回 | 播放器、评论、后台返回 | 音频连续、歌曲信息可见、必要操作可用，返回后接续任务 |
| 自主探索内容 | 浏览音乐推荐、活动或适合自己的商业信息 | 推荐流、推广卡片、偏好反馈 | 内容相关，用户的关闭及拒绝记录生效 |
| 处理不适互动 | 停止接触、提交举报、查询处理结果 | 评论、私信、一起听、系统通知与记录 | 可以及时退出，举报受理后持续可查，结案有说明 |

| R09 | 阅读有价值的评论并控制不适内容 | 公开反馈同时认可交流价值并反映质量问题 | 处理举报、屏蔽与偏好分流；排序重构不进入本期 |

| R11 | 了解所选音质在当前设备上的生效条件 | 单条主观音质反馈；缺少客观测试和设备样本 | 保留需求，先核对设备、传输及实际输出 |
| R12 | 集中管理关注歌手和更新提醒 | 单条相关公开反馈；当前入口和受众规模待核对 | 保留需求，先验证管理路径及提醒负担 |

## 三、歌手作品完整浏览

### 3.1 问题与成立依据

用户沿艺人主页查找其参与的多人合集时，需要在现有作品列表中识别并进入相关专辑。歌曲、专辑和艺人之间的关系未被完整映射，会使已收录作品在该路径中遗漏，增加重复搜索和跨来源核对。

网易云音乐现有热门歌曲、查看全部歌曲、专辑页面及按时间排序能力可以继续使用。需求缺口集中于已确认参与关系的展示和维护。

在iOS 9.6.15的记录中，日文版《メメントモリ Lament Collection Vol.4》专辑署名为Various Artists，歌曲署名关联Bank of Innovation, Inc.；BOI主页能找到英文版，日文版需要另行搜索。网易云公开检索的日文版专辑ID为404473299，英文版为403874212；艺人ID为59602882的专辑列表返回10张专辑，包含英文版，未包含日文版。

BOI官方公告确认两种版本于2026-10-21发行，各42首；发行平台在BOI的参加作品中保留日文合集及Various Artists署名。该案例支持核查作品关联缺口，影响规模通过同类合集样本评估。[官方发行公告](https://boi.jp/news/261021o.html)、[BOI发行平台艺人页](https://www.tunecore.co.jp/artists/bankofInnovation)、[网易云日文版专辑](https://music.163.com/album?id=404473299)。

### 3.2 用户需要与产品响应

| 用户需要 | 产品响应 | 边界 |
|---|---|---|
| 沿艺人主页找到参与作品 | 根据确认的参与关系补齐歌曲、专辑与艺人索引，复用现有列表 | 发行公司字段不能单独证明艺人参与关系 |
| 理解参与身份与范围 | 保留专辑艺人及歌曲参与者，显示合集属性和参与说明 | 只参与部分曲目时标明相关歌曲，避免整张专辑归属失真 |
| 区分语言与独立发行版本 | 使用发行资料补充语言信息，按专辑ID去重 | 日文、英文等独立版本分别保留 |
| 修正漏关联与错关联 | 复用信息纠错入口，附带歌曲、专辑和艺人标识，复核后刷新索引与缓存 | 来源不足时保留原信息及待核对记录 |

关联核对流程为：确认署名来源→比对歌曲参与关系与艺人作品索引→生成缺失关联项→角色和参与范围一致时补齐，冲突时转内容运营复核→刷新列表→验收并保留变更依据。该流程将人工集中在有分歧的差异项。

### 3.3 收益、成本与验证

预期收益为降低已收录作品的路径遗漏，减少查找步骤。主要成本来自元数据核对、索引维护及历史数据修复；主要风险为同名艺人、角色混淆和语言版本错误合并。方案作为P1配套建议，复用现有页面，无需独立作品中心。

验证采用明确参与关系的合集样本：核对关联覆盖和错关联，执行从艺人主页找到指定合集的任务，并检查版本区分及更新后的列表一致性。播放权限继续遵守既有授权。

## 四、听歌流程推广干扰控制

### 4.1 问题与成立依据

用户进入音乐应用后可能立即搜索、识曲、播放或恢复已有任务。推广的时机、占用区域、重复程度与内容相关性共同影响体验。即使音频保持播放，音乐信息被遮挡、操作需要额外关闭和页面路径被改变，仍会增加任务成本。

2026-11-01的记录覆盖以下场景：

| 环节 | 记录中的表现 | 对任务的影响 |
|---|---|---|
| 播放器 | 领时长推广大卡片占用音乐展示区域，音频继续播放 | 影响歌曲信息和页面内容的查看 |
| 返回前台 | 展示全屏广告，包含“点击或扭动手机”跳转提示 | 延迟恢复任务，并存在动作误触风险 |
| 评论及返回 | 出现功能活动内容和赞赏引导 | 用户需要辨别引导与原内容，跨页面可能累积打扰 |
| 免费时长临近结束 | 显示倒计时及看广告续时长等选择 | 需要理解服务状态、奖励和下一步；与会员歌曲受限提示分别处理 |
| 刷新与浏览 | 手势达到一定幅度展开顶部活动 | 用户预期的常规操作与推广触发产生竞争 |
| 不同账号首屏 | 分别进入心动页和推荐页 | 需核对搜索、识曲、个人音乐和模式切换的可发现性 |

心动页保留右上角搜索图标和底部搜索入口。该案例支持测试不同布局下的入口识别、任务完成与内容消费，账号差异成因仍需设置、版本和实验信息核对。音乐推荐与商业推广分别计量。

### 4.2 目标用户与分层

用户权益用于判断可展示内容，当前操作用于判断展示时机。主要分组为未登录、非会员、有效且未临期会员、临期会员；权益状态未知单独记录。免费听歌模式、首页模式和使用任务作为交叉观察维度。

新用户可能需要功能说明；熟悉路径的长期用户更重视接续任务。主动搜索、识曲和播放控制的行为信号优先于历史兴趣推测。意图不明确时保留关键入口和用户选择。

### 4.3 需求与设计原则

| 需求 | 产品响应 | 业务约束 |
|---|---|---|
| 减少推广对当前听歌任务的影响 | 识别当前任务，统一跨页面频控和关闭记录；搜索、识曲、关键播放操作及返回恢复期间保护任务 | 保留符合场景和权益的展示空间，降低重复曝光 |
| 查看歌曲信息并完成操作 | 推广避开歌曲信息、歌词和控制区域；选择固定位置或非阻断形式 | 评价展示质量与有效转化，曝光量同时受体验指标约束 |
| 看到与自身情况相关的内容 | 先过滤权益不适用、已拒绝和频控超限内容，再结合主动行为、兴趣及反馈排序 | 内容匹配遵守个性化选择及隐私规则，关闭个性化后使用受控通用内容 |
| 关闭与拒绝能够生效 | 关闭同活动本次会话不再被动展示；不感兴趣跨会话生效至活动结束或用户恢复；减少同类降低频次和排序 | 同活动不同素材共享反馈，避免换页面或换素材后重新触达 |
| 关键功能始终容易找到 | 一级导航稳定；搜索、识曲、个人音乐等首屏可发现，图标含义和点击范围清楚 | 内容权重可调整，基础入口的可见性、识别性和可达性保持稳定 |
| 理解受限与激励选择 | 会员歌曲权限、免费时长、促销和激励广告分别说明；同队列同状态合并提示 | 进入激励广告前说明观看条件、所得权益及可能的外部跳转 |
| 自主选择常用显示方式 | 用户设置首页落点和可选内容顺序，按账号保存 | 系统按用户主动设置显示首页和可选内容顺序，个性化推荐不自动覆盖这些设置 |

商业广告、会员促销、活动和功能引导分别记录。自动弹出的阻断型功能引导纳入总体打扰额度，非阻断提示计入曝光与页面密度；用户主动打开的帮助按主动任务处理。必要服务和安全通知按独立规则展示。

用户明确选择激励广告后，可以进入相应任务。退出或完成后恢复最新歌曲、队列、位置和播放状态，并重新检查可用权益。日常刷新、浏览及持机动作保持原有功能，广告跳转使用明确点击入口。

### 4.4 收益、成本与验证

预期收益为减少强制关闭、误跳转和恢复成本，提高推广匹配与接受程度。实施需要广告、会员、运营及客户端共享任务和活动标识；频次与内容优化可能影响短期曝光，需要同时观察有效转化、收入及负反馈。

方案整体为P1。基础展示规则、跨页面频控、音乐信息保护、关键入口及必要权益说明先交付；内容匹配和较完整偏好管理在基础流程可用后实施。具体见PRD的功能优先级。

| 验证项 | 核验方式 |
|---|---|
| 任务完成 | 预先指定搜索、识曲、进入歌单、返回播放器等任务，记录完成、失败和放弃，比较步骤与总耗时 |
| 入口可发现性 | 记录首个选择是否正确，以及从首屏可交互到发现入口的时间；覆盖不同首页与账号 |
| 推广干扰 | 分别记录音频连续性、信息遮挡、操作受阻、强制关闭及误跳转 |
| 反馈生效 | 同活动跨页面、跨素材及跨会话复测关闭和拒绝规则 |
| 个性化效果 | 分开观察音乐推荐与商业推广，综合主动播放、收藏、有效转化和负反馈；自动播放与主动选择分别统计 |
| 商业影响 | 结合实际曝光、可归因有效转化及收入指标判断，扣除误触和重复事件 |

任务总耗时包含启动、广告及加载；识曲分别记录启动采集和获得结果的时间，首次系统权限耗时单独标记。任务完成率以预先分配的任务次数为分母，未找到入口和中途放弃均计入未完成；按任务类型分别统计。指标目标通过基线确定。

## 五、评论及陌生互动举报反馈

### 5.1 问题与成立依据

举报提交后，用户需要判断是否受理、当前是否需要补充、处理是否结束，以及结果适用什么后续操作。仅有提交信息时，用户难以区分排队、处理中、材料不足、未认定违规和结果通知遗漏。

2026-11-01的使用反馈中，应用内系统通知显示已提交，后续状态与结案结果在该路径中不可见。历史公开反馈涉及一起听中的骚扰及举报等待；另有评论举报投诉在后续获得最终反馈。证据支持改善进度和结果可见性，尚不能推断后台未处理或所有举报均无结果。[评论举报投诉](https://tousu.sina.com.cn/complaint/view/17394848186)。

评论区同时承载音乐故事和交流。需求区分疑似违规、内容质量、个人偏好和停止接触；个人屏蔽与平台违规认定分别处理，保护正常表达。

### 5.2 需求与产品响应

| 用户需要 | 产品响应 | 关键规则 |
|---|---|---|
| 确认举报已被接收 | 服务端确认后形成可查询记录和受理回执 | 请求失败保留草稿；超时先查询再重试，防止重复提交 |
| 离开原场景后继续查询 | 举报集中记录、系统通知及详情相互关联，复用消息或帮助反馈区域 | 通知失败或设备推送关闭时仍可查询 |
| 理解真实处理进度 | 显示已受理、处理中、待补充、已结案及时间记录 | 规则引擎或人工实际开始处理后，状态才更新为“处理中”；状态说明依据真实处理事件 |
| 知道是否需要补充及等待原因 | 告知必要材料、期限及提交方式；超时给出延迟说明并内部升级 | 排队和处理中均纳入超时检测，用户补充等待与平台等待分别记录 |
| 每次结案都有解释 | 覆盖认定违规、未认定违规、证据不足、不属处理范围、重复关联和撤回等结论 | 提供原因类别、时间和适用的补充或复核操作 |
| 即时停止不适接触 | 可先退出、按意愿屏蔽，再决定是否举报 | 退出不以填写举报为条件；离线本机隔离与账号范围生效分别说明 |

基础交付覆盖受理、查询、补充、结案及通知关联，保证已受理记录能够跟进至结束。合并审核保留每位举报人的独立记录；复核产生新结果版本并保留历史。关键节点提醒包括受理、待补充、首次超时和结案，普通中间变化保留在详情中。

### 5.3 收益、成本与验证

方案为P0，优先保障安全相关处理和反馈的完整性。主要成本来自审核、客服、消息及记录系统协作，分类时限和升级规则由实际能力配置。主要风险包括状态失真、结果发布遗漏、隐私暴露和恶意重复举报。

结案覆盖率、通知生成及结果查看按举报记录和结案版本核对，后台形成但未成功发布的结果同样纳入应发布范围。受理成功率按用户确认提交的去重请求统计；合并案件仍逐个检查举报人的查询能力。复核各轮分别计时，通知生成、送达状态和实际查看分别记录。

任务测试覆盖正常受理、请求超时、待补充、长期排队、未认定违规、证据不足、通知失败、合并审核及复核改判。验收重点为状态真实、记录可找回、每类结案有结果及适用的后续选择。

## 六、方案取舍与交付顺序

### 6.1 评估原则

需求评估使用任务后果、证据强度、影响范围、实施依赖四项依据。单条案例用于界定问题和验证范围；问卷频次用于辅助排序。安全相关需求设立优先保障要求，研发顺序同时考虑技术依赖和可验收范围。

本期采用定性分级，影响人数、实施工时和商业损失未知时保留未知，目标值在基线核对后确定。

| 方案 | 任务后果 | 证据与范围 | 实施依赖 | 定位及优先级 |
|---|---|---|---|---|
| 歌手作品完整浏览 | 部分已收录合作作品在艺人路径中遗漏 | 有明确案例和发行依据，覆盖规模待抽样 | 元数据、作品索引和内容运营，可复用界面 | 配套建议；P1 |
| 听歌流程推广干扰控制 | 增加找歌、查看信息和返回恢复成本，个别时机存在误跳转风险 | 问卷与多场景记录支持，需复测频率和账号差异 | 广告、会员、运营及客户端规则协调 | 重点体验方案；P1 |
| 评论及陌生互动举报反馈 | 举报后难以跟进处理进度及结论；风险场景需要即时退出 | 有使用反馈和公开场景，完整处理链需内部核对 | 举报记录、审核、客服和通知协作 | 安全与信任基础能力；P0 |

举报反馈优先保障受理至结案的完整处理流程；推广控制重点改善核心听歌任务；作品关联通过关系核对与修复补足浏览路径。

### 6.2 本期范围与后续需求

本期交付三项需求的任务流程、规则、异常处理、指标及验收要求。作品浏览复用现有页面；推广控制和举报反馈包含拟议交互。设计结果尚需技术评审、正式版本复测和用户任务验证。

版权采购及替代版本、完整推荐算法重建、个人音乐跨端冲突、云盘批量整理、音质升级和关注管理继续保留在需求池。后续依据版权合作条件、任务失败样本、设备及技术能力安排专项验证。
